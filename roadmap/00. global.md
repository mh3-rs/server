# mh3sp roadmap

An open-source (AGPL-3.0) Rust server for *Monster Hunter Tri* (Wii) online play, that anyone with some Docker
knowledge runs from a README and a guide. [MH3SP](https://github.com/sepalani/MH3SP) (Python) is the reference, not
the target: we aim to do better than it, not to copy it.

This file: what is done, what is left in order, what we could do (rewritten by the [review](../../docs/history/review.md),
2026-10-11). No numbering: the order is the order of the lines; each to-do is ticked in place when done, and a
finished group shrinks into "Done". Each to-do says how it can be done:
**[auto]** by Claude alone, checked by tests and CI; **[lab]** needs a console run; **[user]** needs the user's
decision, input, an account or a push.

What lasts is in the `docs` repository: [`architecture.md`](../../docs/architecture.md) (the numbered decisions),
[`schema.md`](../../docs/schema.md), [`recordings.md`](../../docs/recordings.md) (console sessions, pending and done),
the done milestones in `history/` (the code cites their decisions as "M5 D11"; the roadmap before the review:
[`history/global 2026-10-09.md`](../../docs/history/global%202026-10-09.md)).

## Done

- **Foundations** (M0): the workspace (`wire`, `server`, `testkit`), framing, the 301 packet ids, the corpus and its
  replay harness, CI. Proof: the corpus re-encodes byte for byte; replayed against MH3SP once (M0).
- **Login** (M1): OPN over the Wii's legacy TLS, LMP, accounts in SQLite (support codes as HMAC, UUID public ids),
  terms, maintenance mode. Proof: tests, replays, consoles.
- **The world** (M2): 12 world servers, gates, cities, quests, content from `CONTENT_DIR`, time and day/night. Proof:
  tests, replays, consoles.
- **Multiplayer** (M3): city and quest joins, leader transfer, chat, friends, blacklist, stored messages, the hunter
  profile mapped and validated. Proof: tests, replays, consoles.
- **NAT negotiation and relay** (M4): our own, `p2p` / `relay` / `hybrid`, the relay taking over symmetric NATs and
  failed punches. Proof: tests with simulated NATs, consoles.
- **Parity** (M5): party chat, announcements (in hunts too), stop with warnings, metrics, jumps (Change Gates, "Warp
  to"), quests matching MH3SP's generator (checked by hand). Proof: tests, consoles. Seats and Player Search: tests
  and replays, the console check pending.
- **Packet encryption** (experiment, off by default); malformed packets and discs without our patch refused.
- **Quest bots, sprint 1** (experiment, behind the `bot` feature): a bot joins a quest, links with the consoles,
  follows its hunter ([`experiment-bots.md`](experiment-bots.md)).
- **The review** (2026-10-11): AGPL-3.0, the `docs` repository, this plan.
- **Our own Nintendo login** (2026-10-11, [`history/nintendo login.md`](../../docs/history/nintendo%20login.md)): in
  the binary, AltWFC gone; each console linked to its Wii, bans holding on a new save; OPN's refusals shown on a
  console at last (status 1). Proof: tests, replays through it, consoles.
- **The patch and its CA** (2026-10-11, [`history/patch and CA.md`](../../docs/history/patch%20and%20CA.md)): a CA
  per deployment in `tls_dir`, the patch generated for the `domain` (Riivolution, `wit`, Gecko; PAL and US),
  downloaded from `http://<domain>/patch`; MH3SP's patch refused. Proof: tests, the patch checked on both discs'
  `main.dol`, four lab runs with certificate verification on (Riivolution, `wit`, Gecko, a US console with a PAL one).
- **Public mirrors** (2026-10-14, [`history/docker-hub-github.md`](../../docs/history/docker-hub-github.md)): the
  `mh3-rs` organization; core, `shared`, `tunnel` on GitHub and `mh3rs/server` on Docker Hub, from `main` only, by
  the CI; the README for players, the operator's guide on Docker Hub. Proof: the first run, a tokenless build from
  GitHub, the image pulled on arm64.

## Open questions

Yours to decide, kept open (the user, 2026-10-11; from the solo runs' `questions.md`, now gone). Provisional calls
are built and stand until decided.
- **The API's data model** (`roles`, `users`, `usages`, `tokens`; `schema.md`'s "Built since"): to review, a session
  of its own.
- **Bans and the whitelist**: a ban targets a console and its Wii (`devices`), checked at OPN and LMP. How to allow a
  new console that has no Capcom ID yet (an invitation code? an approval from a list of refused consoles?);
  `access_rules.expires_at` and the `allow` kind exist with no user yet (keep, or drop until needed).
- **The website's sign-in**: failed attempts throttled per email (5 in 15 minutes), so anyone can keep a known email
  locked out; per (email, the visitor's address) would end that. No registration, reset or email yet. A sign-out
  while the API is down can't revoke the token (30 days).
- **The website's end-to-end tests** need the server: its CI can run `main`'s image as a service now
  (`git.pband.ch/mh3-rs/server:latest`). Not wired yet.
- **Decision 9 at LMP** (provisional): a database failure answers with an alert ("Not available right now"), never
  seen on a console at LMP (it might wait instead); the check is pending in `recordings.md`. If it hangs, LMP drops
  again and FMP keeps the alert.
- **Chat commands** (provisional): admins are Capcom IDs in `admins`; an admin command from anyone else answers
  "Unknown command"; `/tell` by Capcom ID or a name only one player online has. Checked on two Dolphins (2026-10-14, `recordings.md`); `admins` in the configuration stays until the schema review (users and roles).
- **Wii Speak** ("Mic chat enabled", seen 2026-10-11): the game shows it by itself (its voice option and a Wii Speak,
  `network_pat_control.cpp:3014-3040`, `:8039-8058`); voice goes console to console, through our relay for relayed
  pairs, at an estimated ~16 kB/s per peer against the relay's 20 kB/s cap. The test is pending in `recordings.md`.
- **The six live quests without small monsters**: their `.dat` files don't exist (Flooded Forest Free-For-All,
  Gobuled Everything in Sight, Shut Up and Fish!, Speak of the Deviljho, Mercy Mission, The Phantom Uragaan). MH3SP's
  `event_whitelist/` and `dev` keep them inline. Options: (a) `CONTENT_DIR` on `dev`; (b) the live branch with those
  six quests' `small_monsters` from `event_whitelist/` (a merge script, not written; recommended); (c) leave it, the
  check at load warns.

## Could do

Not needed for the target; the details of the older plans are in
[`history/global 2026-10-09.md`](../../docs/history/global%202026-10-09.md), the ideas' value and cost in the
[review](../../docs/history/review.md).

- **The core as an API, the website one client of it**: one database, an `openapi.json`, tokens and users
  (`schema.md`); the live world, hunter pages, the event calendar, editing. A Discord bot or a CLI would
  be other clients, anyone's.
- **Bans and a whitelist**, with the game's own refusals (`NtcShut`, `AnsLoginInfo` status 5, `ReqWarning`, the ban
  and wait-queue screens); moderation tooling.
- **Reasons to stay past HR 51**: leaderboards and achievements from quest runs, community events, custom event
  quests.
- **A quest editor** (the user, 2026-10-14): quests made and edited in the website, stored in the database,
  scheduled like the files.
- **Quest bots**: sprint 2 agreed ([`experiment-bots.md`](experiment-bots.md)), then the companion.
- **Gameplay**: joining a quest after departure, chat commands and whispers, system messages, bigger cities.
- **Reach**: other PAL languages, the Japanese version (its own addresses in the patch's table, MH3SP's Wii Shop
  patch), Wii Speak through the relay.
- **The patch applied in the browser** (the user's idea, 2026-10-11): a page where a player picks their image and the
  patch is applied locally (WASM), nothing uploaded; it could also hand out the Riivolution files, served by the
  server for its domain. For an ISO or WBFS (what USB loaders use), patching in place: decrypt the few clusters
  holding the edits, rewrite their hashes (H0–H3), fakesign if loaders need it; a few MB written, no compression. An
  RVZ (Dolphin's) means decompressing and rewriting a ~4.7 GB image: `nod` (`nodtool`'s library) does it, but its
  zstd, lzma and bzip2 are C and it uses `rayon` (a WASM build unchecked), and writing that much needs the File
  System Access API (Chrome and Edge only, from memory). Competes with Gecko and the `wit` image (built 2026-10-11,
  untested on a Wii); all need a real Wii.
- **A port in the patch**: `http://<domain>:<port>/ac` (the game's HTTP library reads it, `d_nhttp.c:3428`), for
  `nas_port` other than 80 without a proxy; costs 5 of the domain's 25 characters, unchecked on a console. A reverse
  proxy covers it (the user, 2026-10-11: stay on 80).
- **Operators**: periodic jobs (purges, backups), `mh3sp init`, an import from MH3SP, a server directory, dashboards.
  The world's names in `mh3sp.toml` too: the world servers (MH3SP's Valor, Beginners, Veterans, Greed, and their
  types), the gates and cities (`City Gate1`, `City1`), the city options (seeking, HR limit, goal: Capcom's labels
  and MH3SP's two additions); the texts already are (`config.rs`).
- **Anti-cheat**: sanity rules from the disc's tables, `NtcCheatCheck` and memory checks, a referee bot.
- **The Nintendo login over HTTPS** (researched 2026-10-11, the user: not before 1.0.0): it would keep the MAC, the
  serial and the token off the wire. The login trusts the Wii's built-in CA (`NHTTPClearRootCA`, its only caller the
  login, `DWCi_Np_CPUCopyFast.c:650`), which no game patch replaces: a code patch there would point it at
  `pat_ca_cert` (OPN's CA, which the patch swaps), plus a certificate named after the login's host (RSA-1024, SHA-1,
  the CA DER 924 bytes), its own listener (443: no SNI), and console runs with verification on.
- **The project**: more quests and the original bytes, a comparison page, RetroAchievements; Dolphin end-to-end
  tests, the server reporting its checkpoints (hooks) to a scripted run.
